The AntsRoute public API (`capi`) lets a client application read and write its own AntsRoute
data — orders, customers, agents, routes — from an external system (ERP, WMS, custom backend...).
It is authenticated with an **API key** rather than the OAuth tokens used by the AntsRoute web app
and mobile app, and every request is scoped to the single enterprise that generated the key.

## Base URL

```
https://app.antsroute.com
```

All endpoints below are prefixed with `/capi`.

## Resources covered

| Resource | What it represents |
| --- | --- |
| Order (`/capi/order`) | A service, delivery or collect — the unit of work performed for a customer |
| Customer (`/capi/customer`) | The party an order is performed for |
| Agent (`/capi/agent`) | The field worker executing routes, their skills, hourly plans and absences |
| Route (`/capi/route`) | A day of work for one agent: an ordered set of orders |
| Skill (`/capi/skill`) | A qualification that can be required by an order or held by an agent |
| Item type (`/capi/item-type`) | A category of goods transported in orders |
| Package (`/capi/package`) | A shipping package, linked to the orders it is attached to |

<Note>
  Terms like "order", "agent" and "customer" are the technical names used throughout this
  documentation. The AntsRoute UI may display different labels per client (e.g. "intervention",
  "technician", "patient") — the underlying API is unaffected by this.
</Note>
